# ADR-002: Embedding Model Abstraction Layer

## Status
Accepted

## Context
Need to select embedding models for semantic search while maintaining flexibility to swap models as quality/cost requirements evolve. Embedding models affect retrieval quality, dimensionality, and provider costs.

## Decision
Abstract embedding model behind a Rust trait (`EmbeddingModel`) with the following contract:
- `embed(text: &str) -> Vec<f32>`: Generate embedding vector
- `dimension() -> usize`: Return vector dimensionality
- `name() -> &str`: Model identifier for logging/tracing
- `provider() -> &str`: Embedding provider name (openai, anthropic, etc.)

Concrete implementations:
- `OpenAIEmbedding`: text-embedding-ada-002 or text-embedding-3-large
- `HuggingFaceEmbedding`: all-MPNet-base-v2, all-MiniLM-L6-v2
- `MockEmbedding`: For testing with deterministic vectors

Provider configuration via environment variables, with fallback to mock for unit tests.

## Alternatives Considered
1. **Direct provider calls throughout codebase**
   - Pros: Simpler initial setup
   - Cons: Tight coupling, hard to test, no model switching, poor separation of concerns

2. **Single model hard-coded**
   - Pros: Simplest code
   - Cons: No experimentation, no A/B testing, locked into provider

## Consequences
- **Positive**: Testable with mock embeddings, easy model swapping, provider-agnostic, clear contract for new models
- **Negative**: Slightly more initial code, need to implement trait for each new model
- **Cost tracking**: Embedding provider and model stored per-batch for cost attribution
